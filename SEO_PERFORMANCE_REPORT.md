Дата: 27.10.2026. Домен: https://ex88.ru. Деплой не выполнялся, DNS, SSL и продакшн-сервер не менялись.

\* Единственная причина 96: ошибка CORS в консоли. API `ex-88.pro` не отвечает на запросы с `localhost`. На ex88.ru (домен должен быть разрешён в CORS API) ошибки не будет.

Главное изменение для SEO: английская версия раньше существовала только в JavaScript на том же адресе, и поисковики её не видели. Теперь у каждого языка свой URL с текстом прямо в HTML. Это те же адреса, что сейчас проиндексированы на ex88.ru (`/ru`, `/en`, `/ru/terms`, `/en/terms`, `/ru/privacy`, `/en/privacy`).

## 2. Исходный аудит

### Продакшн (только чтение: статусы и теги `<head>`)

- Сейчас на ex88.ru работает Next.js за nginx. `/` отдаёт 307 на `/ru/`, затем 308 на `/ru`. `http://` отдаёт 301 на `https://`.
- `http://www.ex88.ru` отвечает 404, `https://www.ex88.ru` не отвечает совсем: нет DNS или сертификата.
- В индексе и `sitemap.xml` два адреса: `/ru` и `/en`. Живые документы: `/ru|en/terms`, `/ru|en/privacy`. `/ru|en/cookies` отдают 404.
- В `robots.txt` есть устаревшая директива `Host`.

## 3. Что сделано

### Производительность

- **Шрифты на своём сервере.** Onest и Unbounded лежат в `assets/fonts` в том же формате, что отдаёт Google: переменные WOFF2, разбитые по алфавитам, с теми же `unicode-range` и `font-display: swap`. Начертания и типографика не изменились. Ушли два сторонних соединения. Для первого экрана подгружаются заранее (preload): на русских страницах кириллица и латиница, на английских только латиница. Латиница на русских страницах тоже нужна сразу: без неё цифры и «Ex88.ru» вызывали сдвиг макета (CLS документов на desktop был 0,114, стал 0).
- **`defer` у `main.js`.** Порядок выполнения сохраняется. Первая проверка тени шапки перенесена в `requestAnimationFrame`, это убрало принудительный пересчёт раскладки при старте.
- **CSS встроен в HTML при сборке** и минифицирован: 50 КБ, около 12 КБ в gzip. Блокирующих запросов CSS больше нет.
- **Скрипт с хешем в имени** (`main.<hash>.js`), поэтому его можно кешировать на год.
- **Кеширование и заголовки:** `dist/_headers` для Netlify и `deploy/nginx.conf`. Скрипт и шрифты кешируются на год (`immutable`), картинки на 30 дней. Плюс `nosniff`, `Referrer-Policy`, `X-Frame-Options`, HSTS.
- Картинки уже были в WebP двух размеров, с `srcset`, размерами и `loading="lazy"` ниже первого экрана. LCP на всех страницах — текст H1, не картинка. Здесь менять было нечего.
- Анимации не тронуты.

### Техническое SEO (`scripts/build.mjs`)

- **URL по языкам** совпадают с продом: `/ru`, `/en`, `/ru|en/terms`, `/ru|en/privacy`, плюс новые `/ru|en/cookies`. Английский текст уже в HTML: сборка подставляет его из словаря `I18N`, поэтому тексты на сайте и в разметке совпадают. На собранных страницах переключатель языка ведёт на адрес другой версии и сохраняет якорь (`/ru#faq` → `/en#faq`).
- **В `<head>` каждой страницы:** абсолютный canonical на себя; `hreflang` ru, en и x-default (→ `/ru`, как сейчас ведёт корень); уникальные title и description на каждом языке; Open Graph и Twitter Cards с картинкой 1200×630 на каждом языке (`assets/img/og-ru.jpg`, `og-en.jpg`).
- **JSON-LD:**
  - на главной: Organization (только данные, которые есть на сайте: юрлицо SATANG DANG & CO COMPANY LIMITED, адрес офиса, год основания, email hello@Ex88.ru), WebSite и FAQPage — 13 вопросов на языке страницы, текст совпадает с видимым FAQ;
  - на документах: BreadcrumbList;
  - рейтингов, отзывов, цен и лицензий в разметке нет: отзывы на сайте пока демо-заглушки.
- **`robots.txt`:** всё открыто, абсолютная ссылка на sitemap, без устаревшей `Host`.
- **`sitemap.xml`:** 8 URL, у каждого `xhtml:link` с hreflang.
- **Редиректы (301, один переход):** `/` → `/ru`; `/index.html` → `/ru`; `/terms`, `/privacy`, `/cookies` и их `.html`-версии → `/ru/...`; `/legal` → `/ru/terms`. В nginx-конфиге ещё http/www → `https://ex88.ru` и удаление `/` и `.html` в конце адреса.
- Заголовки H1–H3 уже были в порядке: один H1 на страницу, логичная иерархия. Alt у картинок корректные: декоративные с `alt=""`.

### Доступность

- Цвет Telegram `#229ED9` → `#1A7DB0`, при наведении `#1B88BD` → `#166A97`. Контраст белого текста 4,56:1. Это единственное заметное визуальное изменение: синяя кнопка стала чуть темнее, зелёная палитра сайта не затронута.
- На карточках Telegram и WhatsApp в блоке контактов подпись `.channel__verb` теперь без прозрачности 0,8, иначе контраст не проходит.
- Ссылка Telegram в шапке получила `aria-label` на обоих языках. У кнопок валют подпись теперь скрытый текст, а флаг скрыт от скринридеров: имя кнопки — «Валюта, которую вы отдаёте RUB».
- Панель офиса стала `<div role="tabpanel">` вместо `<article>`.
- Между ссылками на документы в футере, когда они переносятся на мобильном, появился промежуток 4 px. Так проходит проверка размера цели касания.

## 6. Core Web Vitals

- **Лабораторные (медиана, mobile):** LCP 2,48 с (`/ru`), 2,18 с (`/en`); CLS ≤ 0,012; TBT ≤ 16 мс. Все в зелёной зоне.
- **Полевые данные (CrUX, INP):** для нового сайта их нет, он ещё не выложен. INP не измерялся, TBT не выдаётся за INP. После запуска смотреть PageSpeed Insights и отчёт Core Web Vitals в Search Console через 28 дней.
- PageSpeed Insights для текущего ex88.ru не запускался: по условиям задачи работа шла только с локальным проектом.

## 7. Ограничения

- **CORS API:** с `localhost` калькулятор не получает курсы, поэтому Best Practices 96. На ex88.ru нужен домен в CORS API EX-88 (это уже есть в чек-листе README).
- **Кеш при локальном замере:** локальный сервер не отдаёт заголовки кеширования, поэтому Lighthouse показывает «cache-insight». На проде их выставят `_headers` или nginx.
- **Неминифицированный JS (~6 КБ экономии):** оставлен как есть. Самодельный минификатор без зависимостей ненадёжен, а добавлять для этого зависимость (esbuild/terser) ради 6 КБ до сжатия не стоит.
- **`www.ex88.ru`:** нужны DNS-запись и сертификат. Без них редирект www → apex не заработает. Это изменение DNS/SSL, нужно ваше согласие.
- **Структура URL.** Документы на старом сайте, возможно, имели другие адреса, которых не видно снаружи. В Search Console стоит проверить отчёт «Страницы» и добавить 301 для найденных URL.
- Отзывы — демо-заглушки, в разметку они не попали. Заменить на настоящие до запуска.
- Ссылки WhatsApp пока заглушки (`WHATSAPP_NUMBER`), их подставит заказчик.

## 8. Рекомендации по серверу и выкладке

1. **Хостинг.** На Netlify всё готово: `netlify.toml` собирает `dist/`, а `_redirects` и `_headers` создаются сборкой. На текущем nginx: `node scripts/build.mjs`, затем `dist/` → `/var/www/ex88/dist` и `deploy/nginx.conf` (пути к сертификатам — существующие).
2. Включить Brotli (на Netlify включён по умолчанию, в nginx — модуль `ngx_brotli`) и HTTP/2.
3. **Порядок миграции без потери индексации:**
   1. выложить на тот же домен;
   2. проверить, что `/ru`, `/en`, `/ru|en/terms`, `/ru|en/privacy` отдают 200, а `/` — один 301;
   3. отправить `sitemap.xml` в Google Search Console и Яндекс Вебмастер;
   4. 2–4 недели следить за отчётами «Индексирование» и «Core Web Vitals».
4. **Переход `/` → `/ru`:** сейчас на проде 307, в новой сборке 301. Это корректно, пока корень всегда ведёт на русскую версию.
5. Перед добавлением аналитики обновить политику cookie (правило из CLAUDE.md).
